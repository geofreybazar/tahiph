# TahiPh (Tahi)

Multi-tenant SaaS for wedding fashion designers in the Philippines: a private atelier dashboard, a public website per designer, a client portal, and a super-admin panel.

**Status: Phase 0 in progress. See `docs/roadmap.md`.**

Repository: <https://github.com/geofreybazar/tahiph.git> (**public**; never commit secrets, real project references or customer data).

## Non-negotiable rules

### Tenancy

1. Every tenant-owned table has `tenant_id`, a unique `(tenant_id, id)`, and composite foreign keys to other tenant-owned tables.
2. Never trust a tenant ID or role from the frontend. `X-Tenant-Id` is only a request, validated against membership every time.
3. Feature modules use only the scoped Prisma client. The identity client is only for `common/auth`; the platform client is only for `modules/platform`.
4. A new tenant model must be added to the registry, enable RLS in its migration, and have a cross-tenant test.
5. No raw SQL without an explicit `tenant_id` filter and a security review flag.
6. No nested writes to tenant models unless the path is allowlisted.
7. Another tenant's record returns 404.
8. **RLS doesn't protect against API bugs**, because the API role bypasses it. Don't reason as though it does. See `docs/security.md` §4.

### Roles

9. Tenant roles are owner, admin and staff. Super-admin is separate, in `platform_admins`.
10. Staff see per-client money, but never revenue, profit, expenses, total receivables or tenant-wide payment lists. Enforce this in the API, not only in the UI.

### Data

11. Money is integer centavos, with no floats in money logic.
12. Moments are stored as UTC `timestamptz`; calendar days as `date`; display and month boundaries use Asia/Manila.
13. Payments and stage events are append-only. Measurement records aren't edited. Balances are derived.
14. There's no `orders` table: a wedding project is the order (ADR 0007).

### Security

15. The Supabase secret key and database credentials stay in `apps/api`. Nothing secret goes under `VITE_` or `NEXT_PUBLIC_`.
16. `apps/web` calls the API from its server. Designer subdomains are never CORS origins.
17. Portal pages are never cached. Public cached pages must be keyed by tenant.
18. Portal cookies are host-only. Never `Domain=.tahi.ph`.
19. Storage keys are generated by the API, and uploads use intent → upload → confirm.

## Coding conventions

- TypeScript strict mode. Avoid `any`.
- Zod schemas in `packages/shared` are the source of truth for requests. That package never imports NestJS, Prisma or server-only code.
- Modules interact through exported services, not each other's tables or repositories.
- Prefer simple code over abstraction. Add abstractions for real duplication, not expected duplication.
- Files in kebab-case. Prisma and database naming are in `docs/database-conventions.md`.

## API summary

REST under `/api/v1`, with `{ success, data, meta?, timestamp }` and `{ success, statusCode, error: { code, message, details }, timestamp, path }`. Full details are in `docs/api.md`.

## Testing

- Business rules, money and date boundaries have unit tests.
- Tenant isolation is tested against real Postgres, never mocks.
- Every feature module has a cross-tenant test and role tests.
- CI runs the registry check, RLS audit and Data API access test.

## Git

- Branch from `main`: `feat/...`, `fix/...`, `docs/...`, `chore/...`.
- Conventional Commit messages.
- Migrations are committed with the code that needs them. Applied migrations aren't edited.
- Never commit `.env` files.

## Rules for Claude Code

- Read the relevant docs before changing code in that area.
- Don't commit, push, deploy or run migrations against a shared database unless the owner asks.
- Don't change an established decision without discussing it and getting approval. Mark your own additions as Proposed.
- Don't claim a command exists until it's configured, and don't claim something works without running it.
- Keep CLAUDE files and `docs/` consistent in the same change.
- Fetch current library docs before relying on an API. This stack changes quickly.
- Flag any raw SQL, new unscoped client use, or auth change for security review.
- Only work within the current roadmap phase.
